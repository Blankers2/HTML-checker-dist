§01 · The Problem

익숙한 검수 풍경,
10개 파일을 동시에 띄워야 했던 그날들.

01
한국어 누락 검출

영어/일본어로 번역된 페이지에 한국어 문구가 섞여 들어와도 긴 페이지를 위에서 아래까지 일일이 스크롤하며 찾아야 했습니다. 이미지로 가려진 텍스트는 거의 발견 불가능.

Human Error · High
02
TM 일관성 확인

"Cotton Foot Shampoo"가 본문 곳곳에서 동일하게 번역됐는지, 용어집(TM)과 어긋난 단어는 없는지 — 단어별로 Ctrl+F를 반복하며 두 창을 번갈아 봐야 했습니다.

Toil · Repetitive
03
원본 대조 비효율

번역본을 보다가 "이거 원본이 뭐였더라?" → 한국어 원본 파일을 다시 열고 위치를 찾기까지 평균 30초. 하루 100번 반복하면 시간이 어디로 가는지 알 수 있습니다.

Context Switch · Costly

검수 도구는 검수자의 시간을 아끼는 방향으로 진화해야 합니다.

§04 · Architecture

가장 단순한 도구가
가장 오래 살아남습니다.

단일 파일. 의존성 0. 백엔드 없음.

모든 로직은 한 개의 index.html 안에 살아있습니다. 외부 라이브러리도, 빌드 도구도, 패키지 매니저도 필요하지 않습니다.

§05 · The Protocol

정직한 코드,
읽으면 그대로 동작.

postMessage Bridge

parent와 iframe은 ID로 매칭되는 비동기 메시지로 통신합니다. 한 iframe에 여러 명령을 동시에 발사해도 응답이 섞이지 않습니다.

모든 명령(search, korean, setScroll, goBlock)이 같은 패턴. 전체 프로토콜 8개가 끝.

bridge.js — request/response JS
// parent → iframe 비동기 메시지 (ID 기반) let _msgId = 0; const pending = new Map(); async function sendMsg(lang, payload) { const id = ++_msgId; return new Promise(resolve => { pending.set(id, resolve); $(lang + 'Frame') .contentWindow .postMessage({ ...payload, id }, '*'); }); } // iframe 응답 수신 window.addEventListener('message', e => { const { t, id, r } = e.data; if (id && pending.has(id)) { pending.get(id)(e.data); pending.delete(id); } }); // 사용 예 const result = await sendMsg('en', { t: 'search', queries: [{ q: 'Wash Your Feet', cls: 'oy-search-hl-0' }] });
