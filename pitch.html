§01 · The Problem

검수자가 매일 마주하는
세 가지 비효율.

01
미번역 한국어 누락

영어/일본어로 번역된 페이지에 미번역 한국어 텍스트가 섞여 있어도 페이지 처음부터 끝까지 스크롤하며 눈으로 찾아야 했습니다. 이미지로 가려진 텍스트는 거의 발견 불가능.

Human Error · High
02
TM 일관성 검수의 한계

브랜드명·옵션명·제품라인명이 공식 TM 기준대로 모든 위치에서 동일하게 번역됐는지 — 단어별로 Ctrl+F를 반복하며 두 창을 번갈아 보는 수밖에 없었습니다.

Toil · Repetitive
03
KO 원본 대조의 비효율

번역본 검수 중 "이거 원본은?" → KO 원본 파일을 다시 열고 해당 위치 찾기까지 평균 30초. 하루 100번 반복하면 50분이 그 자리에서 사라집니다. 삭제 이미지 누락도 발견 어려움.

Context Switch · Costly

검수 도구는 검수자의 시간을 아끼는 방향으로 진화해야 합니다.

— 이 도구를 만든 이유

CASE 01 · TM 다중 검색

브랜드 · 제품 · 옵션 동시 검수

Shea Butter LHA Baby Scrub Stick

올리브영 글로벌몰 납품 검수 — 한 페이지에 브랜드명, 제품라인명, 옵션명, 제품명, 카테고리가 모두 등장합니다. 기존에는 5번을 따로 Ctrl+F로 검색해야 했지만,

"브랜드명, 제품명, 다른 제품의 같은 제품라인명 모두 검색 가능해서 검수 프로세스가 최적화되었습니다."

§06 · Protocol

정직한 코드,
읽으면 그대로 동작합니다.

postMessage Bridge

parent와 iframe은 ID로 매칭되는 비동기 메시지로 통신합니다. 한 iframe에 여러 명령을 동시에 발사해도 응답이 섞이지 않습니다.

모든 명령(search · korean · setScroll · goBlock)이 같은 패턴. 전체 프로토콜 8개가 끝입니다.

bridge.js · request/response JS
// parent → iframe 비동기 메시지 (ID 기반) let _msgId = 0; const pending = new Map(); async function sendMsg(lang, payload) { const id = ++_msgId; return new Promise(resolve => { pending.set(id, resolve); $(lang + 'Frame') .contentWindow .postMessage({ ...payload, id }, '*'); }); } // 사용 예 — 다중 검색 const result = await sendMsg('en', { t: 'search', queries: [ { q: 'Shea Butter', cls: 'oy-search-hl-0' }, { q: 'LHA', cls: 'oy-search-hl-1' }, { q: 'Baby', cls: 'oy-search-hl-2' }, ] });
